# Historias de Usuario

*Proyecto:* Gestor de Tareas y Proyectos  
*Integrantes:* Mariana Rojas, Sofía Combita, Samuel Felipe Rojas

---

| ID | HISTORIA DE USUARIO | CRITERIOS DE ACEPTACIÓN |
| --- | --- | --- |
| HU-01 | Como miembro de un equipo, quiero crear tareas simples y compuestas para estructurar el trabajo del proyecto. | Dado que estoy en el panel principal, cuando creo un proyecto contenedor y le añado subtareas, entonces el sistema guarda la jerarquía de forma correcta. |
| HU-02 | Como usuario del sistema, quiero cambiar el estado de una tarea cumpliendo las reglas del flujo de trabajo establecido. | Dado que una tarea se encuentra en estado "En curso", cuando selecciono enviarla a "En revisión", entonces el cambio de estado se efectúa de manera exitosa. |
| HU-03 | Como usuario, quiero poder deshacer (undo) la última acción ejecutada si me equivoqué al modificar una tarea. | Dado que acabo de cambiar la prioridad o el estado de una tarea, cuando accedo a la función "Deshacer", entonces la tarea regresa a su estado previo. |
| HU-04 | Como gestor de proyectos, quiero utilizar plantillas para crear proyectos recurrentes sin tener que reconstruir todo desde cero. | Dado que elijo una plantilla de proyecto predefinida, cuando confirmo su uso, entonces se despliega automáticamente todo el árbol de tareas correspondiente. |
| HU-05 | Como usuario, quiero filtrar y ordenar las tareas por prioridad, fecha límite y responsable para organizar mis prioridades diarias. | Dado que tengo un listado extenso de actividades, cuando aplico el filtro por "Fecha límite", entonces el sistema organiza las tareas cronológicamente. |
| HU-06 | Como usuario, quiero interactuar con el sistema tanto mediante una consola de comandos como a través de una interfaz gráfica sencilla (Swing) sobre un núcleo compartido. | Dado que inicio la aplicación, cuando realizo cambios en la interfaz gráfica, entonces los datos en el núcleo se actualizan de la misma forma que en la consola. |
